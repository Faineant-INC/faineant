# Supabase Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Supabase project locally and define the complete database schema (all tables, enums, extensions) with the booking no-overlap constraint enforced and tested in Postgres.

**Architecture:** Schema-as-SQL-migrations managed by the Supabase CLI. `User` splits into Supabase-managed `auth.users` + a `public.profiles` table (1:1, shared PK). Auth-session tables (`EmailVerificationToken`, `RefreshToken`) and `UploadRecord` are dropped — Supabase Auth and Storage own those concerns. Overlapping bookings are made impossible by a Postgres `EXCLUDE` constraint rather than application-level serializable transactions.

**Tech Stack:** Supabase CLI, PostgreSQL 15, extensions (`btree_gist`, `postgis`, `pg_trgm`, `moddatetime`, `pgtap`), pgTAP for DB tests.

**Scope of THIS plan:** project init + local stack + schema + extensions + booking exclusion constraint + pgTAP smoke/constraint tests. **Out of scope (later plans):** RLS policies, auth triggers, RPCs, Edge Functions, Storage, geography columns/search, client rewrites, `apps/api` teardown.

**Prerequisite:** Supabase CLI installed (`brew install supabase/tap/supabase`), Docker running. Remote project ref: `dujuixrqfarkcbdhqlkn` (link is optional for this plan — all work is local).

**Naming convention:** SQL uses `snake_case` table/column names (Postgres idiom), replacing Prisma's `camelCase`. Client type generation handles the mapping later.


- [ ] **Step 2: Write the bookings SQL**

Paste into the generated file:
```sql
create table public.bookings (
  id                       uuid primary key default gen_random_uuid(),
  client_id                uuid not null references public.profiles(id),
  service_id               uuid not null references public.services(id),
  provider_profile_id      uuid not null references public.provider_profiles(id),
  status                   booking_status not null default 'PENDING',
  start_time               timestamptz not null,
  end_time                 timestamptz not null,
  total_price_in_cents     integer not null,
  notes                    text,
  location                 text,
  latitude                 double precision,
  longitude                double precision,
  stripe_payment_intent_id text,
  created_at               timestamptz not null default now(),
  updated_at               timestamptz not null default now(),
  -- No two active bookings for the same provider may overlap in time.
  constraint bookings_no_overlap exclude using gist (
    provider_profile_id with =,
    tstzrange(start_time, end_time) with &&
  ) where (status in ('PENDING','CONFIRMED','IN_PROGRESS'))
);
create index bookings_client_idx on public.bookings(client_id);
create index bookings_provider_idx on public.bookings(provider_profile_id);
create index bookings_status_idx on public.bookings(status);
create index bookings_start_idx on public.bookings(start_time);
create trigger bookings_set_updated_at before update on public.bookings
  for each row execute function extensions.moddatetime(updated_at);
```
